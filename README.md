# soroban-gauge

A Rust CLI and GitHub Action that runs a compiled Soroban contract (`.wasm`) through
declarative scenarios on a local copy of the Soroban host VM, records per-invocation
resource use (CPU instructions, memory, ledger reads and writes, bytes, events, an
estimated fee), stores the result as a deterministic baseline in git, and on every pull
request posts a per-function diff and fails CI when a metric regresses past your thresholds.
It also reports static facts about the Wasm file (size, hash, imports, exports, metadata).

> The numbers are **estimates from the pinned host version**, not exact network fees.
> See [docs/limitations.md](docs/limitations.md).

## Quickstart (about 60 seconds)

Needs Rust 1.91 or newer to build the tool, and a compiled contract.

```bash
# 1. Install (or download a release binary and its checksums.txt from the Releases page)
cargo install --locked --git https://github.com/OWNER/soroban-gauge gauge-cli

# 2. In your contract project: write a starter config and an example scenario
soroban-gauge init
#    edit soroban-gauge.toml: point [[contract]].wasm at your built .wasm
#    edit scenarios/example.toml: use your contract's function names and arguments

# 3. Record the baseline and commit it
soroban-gauge snapshot
git add .soroban-gauge/baseline.json

# 4. Check a change against it (this is what CI runs)
soroban-gauge check
```

Exit codes: `0` ok, `1` regression over threshold, `2` usage or config error, `3` scenario
execution failure, `4` baseline/environment version mismatch, `5` I/O or parse error.

## Commands

| Command | Purpose |
|---|---|
| `init` | Write a starter `soroban-gauge.toml` and `scenarios/example.toml` (refuses to overwrite without `--force`). |
| `inspect <wasm>` | Static report on a Wasm file (`--format table\|json`). Never executes the Wasm. |
| `run` | Execute all scenarios and write a run report (`--out`, default `target/soroban-gauge/report.json`). Does not touch the baseline. |
| `snapshot` | Run, then write or update the baseline (`--only <scenario>` updates just that scenario). |
| `diff` | Compare two result files: `--baseline`, `--current`, `--format table\|markdown\|json`, `--fail-on regression\|any-change\|never`. |
| `check` | `run` then `diff` against the configured baseline in one step. |
| `calibrate` | Not implemented in this version (see Roadmap); exits with code 2. |

Global flags: `--config <path>`, `--quiet`, `-v/--verbose` (repeatable), `--color auto|always|never`
(output contains no ANSI escapes today, so `--color` has no effect yet). Machine output goes to
stdout; logs go to stderr.

## GitHub Action

```yaml
- uses: OWNER/soroban-gauge@v0.1.0   # pin a release; pin by commit SHA for the strictest setup
  with:
    config: soroban-gauge.toml
```

Details, required permissions and a full workflow: [docs/ci.md](docs/ci.md).

## How this differs from other tools

Facts only:

1. It runs offline on a local host VM, so CI needs no RPC endpoint, funded account or deployed fixture.
2. It measures the compiled Wasm using declarative scenario files, so no Rust test code has to be added.
3. It records each invocation independently and supports multi-step scenarios.
4. Its baseline is byte-stable in git (no timestamps) and detects environment drift.
5. It includes static Wasm inspection in the same report.
6. A `calibrate` command to compare local estimates against network simulation is planned (see Roadmap).

RPC-based measurement reflects live network settings, while local measurement reflects the pinned
host version, so you may want both. Other tools cover security scanning; this one measures resource
regressions only.

## Limitations

See [docs/limitations.md](docs/limitations.md). In short: estimates, not network fees; costs differ by
protocol version; scenarios cover only what you write.
